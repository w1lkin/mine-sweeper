# 微信小游戏 · 扫雷（HTML5）设计文档

- 日期：2026-07-27
- 状态：已确认（待评审）

## 1. 目标与形态

实现一个**移动端优先**的扫雷小游戏，以纯 HTML5 单页方式运行，可在手机浏览器与微信内置浏览器（webview）中直接打开游玩。

- **不是**微信小游戏独立工程（无需微信开发者工具），但提供"分享给朋友"的微信 webview 分享包装。
- 通过 `card-share`（share-card-generator）skill 生成分享卡片页，包含本局成绩与二维码，支持长按保存。

## 2. 游戏规则

### 2.1 难度（三档，经典配置）

| 难度 | 列 × 行 | 雷数 |
|------|---------|------|
| 初级 | 9 × 9   | 10   |
| 中级 | 16 × 16 | 40   |
| 高级 | 30 × 16 | 99   |

（注：高级为 30 列 × 16 行，横向较宽，移动端采用横向滚动或缩放适配。）

### 2.2 交互

- **点按**：翻开格子。
- **长按 / 右键**：在格子插旗 / 取消旗（标记疑似雷）。
- **首次点击安全**：第一下点击保证不踩雷（生成棋盘时延迟布雷，避开首点及其邻域）。
- 翻到数字为 0 的空格时，自动连锁展开周围 8 格（ flood fill）。
- 标雷计数显示：剩余雷数 = 总雷数 − 已插旗数。

### 2.3 胜负判定

- **胜利**：所有非雷格均被翻开。
- **失败**：翻到雷。
- 计时：从首次有效点击开始计时，胜利或失败时停止。

## 3. 最近 10 次记录（localStorage）

- 存储 key：`minesweeper_records`
- 数据结构：`Array<Record>`，最多保留 10 条，超出截断（保留最新）。
- 单条 `Record`：

  ```ts
  {
    date: string;        // ISO 时间，如 2026-07-27T14:03:00
    difficulty: 'easy' | 'medium' | 'hard';
    result: 'win' | 'lose';
    time: number;        // 用时（秒）
    cellsLeft: number;   // 失败时剩余未翻开非雷格数（胜利为 0）
  }
  ```

- 排序：按时间倒序，最新记录置顶展示在首页"历史战绩"区。
- 写入时机：每局结束（胜或负）后写入。

## 4. 分享页（card-share skill）

使用已同步的 `share-card-generator` skill 产出分享能力：

1. **独立分享页 `share-card.html`**：基于 skill 的 `references/card-template.html` 模板，填入本局成绩（标题=游戏名、副标题=难度、features=用时/胜负、二维码=游戏链接），浏览器打开后可下载 1200×1600 PNG 作为 og:image。
2. **游戏内分享**：复用 skill 的 `references/share-button-pattern.js` 逻辑，点击"分享给朋友"按钮时，在离屏 canvas（1200×1600）绘制同款卡片，叠加二维码，通过浮层展示图片，支持微信内长按保存。
3. 主题：默认清新绿（`#81C784`）；如后续需要可切换暗黑金。

## 5. 文件结构

```
mine-sweeper/
  index.html        游戏主页面（难度切换 + 棋盘 + 计时 + 战绩 + 分享按钮）
  style.css         移动端优先样式
  game.js           游戏逻辑、棋盘生成、交互、localStorage 记录、分享调用
  share-card.html   card-share skill 生成的分享页（或运行时生成）
  docs/superpowers/specs/2026-07-27-minesweeper-design.md
```

## 6. 数据流向

1. 用户选难度 → `game.js` 初始化棋盘（延迟布雷，首点安全）。
2. 用户点击/长按 → 更新格子状态、连锁展开、判定胜负、更新计时与剩余雷数。
3. 胜负产生 → 组装 `Record` 写入 `localStorage` → 刷新战绩列表。
4. 用户点"分享" → 读取本局 `Record` → 生成分享卡（离屏 canvas + 二维码）→ 浮层展示。
5. 用户点"生成分享页" → 产出/打开 `share-card.html`。

## 7. 验收标准

- [ ] 手机浏览器与微信 webview 内可正常加载并游玩。
- [ ] 三档难度可切换，棋盘尺寸/雷数正确。
- [ ] 首次点击安全，翻开空格连锁展开正确，胜负判定正确。
- [ ] 长按插旗、剩余雷数计数正确。
- [ ] 每局结束写入记录，刷新页面后最近 10 条战绩保留且按时间倒序。
- [ ] 分享卡片包含本局难度/用时/胜负与二维码，可长按保存为图片。
- [ ] 无控制台报错，移动端布局无溢出。

## 8. 范围之外（YAGNI）

- 不接入微信 JSSDK 真实分享 API（仅 webview 分享包装 + 卡片长按保存）。
- 不做排行榜后端、不做账号系统、不做音效（除非后续要求）。
- 不做自定义难度输入。
